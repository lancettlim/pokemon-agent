# pokemon-agent

This repository contains planning and specification documents for the Pokémon
Champions competitive data platform and its first dataset artifact.

## Current focus

`dataset_version 0.3.0` is the current published release — the core ingestion
→ normalization → release pipeline, Phase 4 team-card renderer, and M6
analytics dashboard are all built. Current development is focused on Team
Analyst workflows, refresh/history observability, and accumulating enough
snapshot history to support honest release-to-release comparisons. See
`docs/roadmap.md` for the active next-development plan and `docs/todo.md` for
repository status.

**Live dashboard:** https://lancettlim.github.io/pokemon-agent/dashboard/

## Repository structure

- `data/staging/` — raw source snapshots before normalization (gitignored,
  regenerated by the extractors)
- `data/normalized/` — normalized, join-ready tables (gitignored, regenerated
  by `make dbt-build`)
- `data/marts/` — Phase 3 flat analytical exports/dashboard tables
  (gitignored, regenerated by `make dbt-build`)
- `data/assets/` — downloaded sprite/icon image cache (gitignored,
  regenerated by the Bulbagarden extractor and the renderer)
- `releases/data/` — release CSVs and bundled images for 0.1.0–0.3.0. From
  0.4.0 a release is a GitHub Release asset (a zip plus its sha256, cut by
  `.github/workflows/cut-release.yml`) and only its manifest and changelog
  are committed; see `docs/dataset-spec.md`'s "Distribution"
- `releases/manifests/` — versioned dataset manifests (from 0.4.0 their
  `package` block names the Release asset's URL and sha256)
- `releases/changelogs/` — versioned dataset changelogs
- `reports/validation/` — validation artifacts for release gates
- `docs/dashboard/` — the generated static dashboard site — unlike the
  `data/` directories above, this **is** committed to git, since GitHub
  Pages serves it directly with no build step (see `docs/dashboard.md`).
  Build it with `make dashboard` (dbt build → `render-share-cards` →
  `build-dashboard`); every view has a `#/...` route, listed in
  `docs/dashboard.md`'s "Routes"
